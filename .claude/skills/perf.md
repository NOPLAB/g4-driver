# パフォーマンス改善

指定されたコードのパフォーマンスを分析し、最適化を行います。

## 手順

1. **対象の特定**: ユーザーが指定したファイル、関数、またはコード範囲を読み込む
2. **分析**: 以下の観点でパフォーマンスを分析する

### 共通
- 不要なアロケーション（Vec、String、Box等）
- ループ内の重複計算
- 不要なクローン/コピー
- アルゴリズムの計算量（O(n²)等）
- 条件分岐の最適化（早期リターン、分岐予測）

### 組み込み（no_std）向け
- 浮動小数点演算の削減（固定小数点化、ルックアップテーブル）
- 三角関数の近似・事前計算
- Mutex/Criticalセクションの最小化
- スタック使用量
- インライン化の検討（#[inline]）
- 割り込みレイテンシへの影響

### デスクトップ向け
- 非同期処理の効率
- キャッシュの活用
- 並列処理の可能性

3. **提案**: 改善点を効果の大きい順にリストアップし、トレードオフを説明する
4. **確認**: ユーザーに実施する改善を選択してもらう
5. **実装**: 承認された改善のみを実施する
6. **検証**: ビルドが通ることを確認する

## 重要事項

- 計測なき最適化は悪。可能なら改善前後の比較方法を提案する
- 可読性とのトレードオフを明示する
- 早すぎる最適化を避ける。ボトルネックを特定してから改善する
- マイクロ最適化より、アルゴリズム改善を優先する
